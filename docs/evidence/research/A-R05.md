- **A-R05｜排程未啟動、執行失敗與交付失敗，如何區分？** 官方分別提供 `last_fire_error`、`last_error`、`last_delivery_error`，不能只看單一成功／失敗狀態。([hermes-agent.nousresearch.com](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron))
- **排程未啟動：**在 hosted／managed-cron 環境，排程交接 gateway 失敗會留下含時間與原因的 `last_fire_error`；因執行未開始，可能沒有執行紀錄或 `last_status`。另若執行前設定檢查不通過，則記為 `blocked_config`，不呼叫模型。([hermes-agent.nousresearch.com](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron))
- **執行失敗：**`last_error` 保存精簡錯誤；連線失敗的詳細 traceback 位於 `cron/output/<job_id>/` 執行文件的 `## Error`。即使 `last_fire_error` 與 `last_delivery_error` 都是空白，也不代表 agent 執行成功。([hermes-agent.nousresearch.com](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron))
- **交付失敗：**agent 成功但交付失敗，記為 `last_status: delivery_failed`，原因另存 `last_delivery_error`，不增加 agent 的 `failure_streak`。**診斷推論：**應先定位排程交接、執行或交付哪一層出錯，再判斷處置，避免盲目重跑。([hermes-agent.nousresearch.com](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron))
